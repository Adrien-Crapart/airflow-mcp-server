An MCP (Model Context Protocol) server exposing tools to manage an Apache Airflow
instance via an HTTP API (FastAPI). This repository includes handlers, the
Airflow client, and both unit and integration tests.

## Quickstart (Windows PowerShell)

```powershell
# Install uv (if needed)
powershell -ExecutionPolicy ByPass -Command "irm https://astral.sh/uv/install.ps1 | iex"

# Sync dependencies and create the virtual environment
uv sync

# Activate the environment (Windows PowerShell)
.venv\Scripts\Activate.ps1

# Run the server in development mode
uv run uvicorn airflow_mcp_server.server:create_app --factory --reload --host 127.0.0.1 --port 8000
```

## Exposed capabilities

The server exposes the following MCP tools:

- DAGs
	- `airflow_dag_list` — list DAGs
	- `airflow_dag_trigger` — trigger a DAG
	- `airflow_dag_pause` / `airflow_dag_unpause` — pause / unpause a DAG
- Tasks
	- `airflow_task_list_instances` — list task instances for a `dag_id`/`run_id`
	- `airflow_task_retry` — request a retry for a task
- Logs
	- `airflow_task_logs` — fetch logs for a task
- Connections
	- `airflow_connection_create` — create / update a connection
- Health
	- `airflow_health_check` — MCP server health
- Discovery
	- `airflow_tools_list` — list available tools (module, signature, docstring, input model)

Detailed capability documentation is available at `docs/mcp_capabilities.md`.

## Endpoints and discovery

- `POST /tool/{tool_name}` — invokes an MCP handler. Expected payload: `{ "params": { ... } }`.
- `POST /tool` — fallback endpoint accepting `{ "tool_name": "...", "params": { ... } }`.
- Interactive OpenAPI UI: `GET /docs` (auto-generated by FastAPI).

To discover available tools dynamically, call the discovery tool:

```bash
curl -s -X POST http://localhost:8000/tool/airflow_tools_list \
	-H 'Content-Type: application/json' -d '{"params": {}}' | jq .
```

Or via the fallback endpoint:

```bash
curl -s -X POST http://localhost:8000/tool -H 'Content-Type: application/json' \
	-d '{"tool_name": "airflow_tools_list", "params": {}}' | jq .
```

## Examples (curl)

Call a tool (general structure):

```bash
curl -s -X POST http://localhost:8000/tool/{tool_name} \
	-H 'Content-Type: application/json' \
	-d '{"params": {...}}' | jq .
```

Concrete examples:

- List DAGs

```bash
curl -s -X POST http://localhost:8000/tool/airflow_dag_list \
	-H 'Content-Type: application/json' \
	-d '{"params": {"limit": 100, "offset": 0}}' | jq .
```

- Trigger a DAG

```bash
curl -s -X POST http://localhost:8000/tool/airflow_dag_trigger \
	-H 'Content-Type: application/json' \
	-d '{"params": {"dag_id": "example_bash_operator", "conf": {}}}' | jq .
```

- Fetch task logs

```bash
curl -s -X POST http://localhost:8000/tool/airflow_task_logs \
	-H 'Content-Type: application/json' \
	-d '{"params": {"dag_id": "my_dag", "run_id": "my_run", "task_id": "my_task", "try_number": 1}}' | jq .
```

- Create a connection

```bash
curl -s -X POST http://localhost:8000/tool/airflow_connection_create \
	-H 'Content-Type: application/json' \
	-d '{"params": {"conn_id": "my_conn", "type": "http", "host": "example.com", "login": "u", "password": "p", "port": 123}}' | jq .
```

## Environment variables

- `AIRFLOW_BASE_URL` (default `http://localhost:8080`)
- `AIRFLOW_USERNAME`, `AIRFLOW_PASSWORD` (BasicAuth credentials; empty by default)
- `AIRFLOW_VERSION` (`2` or `3`, affects `/api/v1` vs `/api/v2`, default `2`)
- `MCP_SERVER_HOST`, `MCP_SERVER_PORT` (MCP server configuration)

## Tests

Activate the virtual environment and run the test suite:

```powershell
.venv\Scripts\Activate.ps1
.venv\Scripts\python.exe -m pytest -q
```

Run integration tests only (set `AIRFLOW_BASE_URL` if needed):

```powershell
#$env:AIRFLOW_BASE_URL = 'http://localhost:8080'; .venv\Scripts\python.exe -m pytest tests/integration -q
```

Integration tests include a fixture that automatically falls back to an HTTP mock
if Airflow is unreachable or requires authentication.

## CI

A GitHub Actions workflow is provided at `.github/workflows/ci.yml` to run
the test suite on multiple Python versions.

## Contributing / adding a tool

1. Create a new module in `airflow_mcp_server/handlers/` that exports a `TOOLS` dict mapping tool names → coroutine handlers.
2. Add a Pydantic model (if useful) in `airflow_mcp_server/schemas.py` and register it in `TOOL_INPUT_MODELS`.
3. Add unit tests in `tests/unit/` and optional integration tests in `tests/integration/`.
